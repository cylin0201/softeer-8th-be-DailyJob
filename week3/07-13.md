###### 2. 가장 막혔던 문제와 해결 과정
- 문제 상황 또는 증상: http://localhost:8080/main/index.html로 접속하면 {{header_menu}} 같은 치환 전 플레이스홀더가 날것으로 노출됐다.
- 처음 추측한 원인: /main/index.html 경로가 등록되지 않아 정적 리소스로 폴백되면서 템플릿 파일이 그대로 서빙되는 것.
- 원인을 확인하기 위해 시도한 방법: 라우팅·StaticResourceController·경로 파싱을 코드 레벨로 분석함.
- 실제 원인: 컨트롤러가 렌더링하는 템플릿(main/comment/mypage 3종)이 서빙 대상인 static/ 안에 있어 직접 요청으로 노출됨. 더 나아가 정규화 없는 원문 경로라 /../logback.xml로       
  디렉토리 탐색까지 뚫리는 것을 확인.
- 해결 방법: 근본 대책(경로 정규화+봉쇄, 템플릿 분리)을 정리해둠.

###### 3. 오늘 아쉬웠던 행동(개발과 관련된 것)
- 비효율적이었던 접근/놓치거나 부족했던 점: CreateCommentController 초안에 결함 3개(성공 시 응답 누락, 예외를 던지는 findById를 == null로 오해→500, parseLong 미방어→500)가 있었음.
- 그렇게 된 원인: 성공/실패 경로를 직접 실행해보지 않았고, 재사용한 서비스 메서드의 계약(예외 vs null 반환) 을 확인하지 않은 채 작성했다.
- 다음에는 다르게 해볼 구체적인 행동: 컨트롤러 작성 직후 성공·실패·미인증 경로를 각각 테스트로 고정하고, 호출하는 서비스 메서드의 반환/예외 규약을 먼저 확인한 뒤 분기 로직을 짠다.
