###### 2. 오늘 가장 의미있었던 기술적 판단
- 내가 내린 판단: HashMap.get()을 이용해 확장자 기반 MIME 타입 검색을 O(1)로 최적화
- 그렇게 판단한 이유: Map 순회 방식이 파일 서빙할 때마다 비효율적이라는 점을 캐치했고, 파일 경로에서 String.lastIndexOf()로 확장자를 추출한 후 HashMap.get()으로 바로 조회하는 게 훨씬 효율적이라고 판단
- 고려했지만 선택하지 않은 대안: 정규식(regex)으로 확장자 추출 (불필요한 오버헤드)
- 이 판단이 코드 품질/테스트/유지보수에 미친 영향: 새로운 MIME 타입 추가 시 단순히 Map에 한 줄만 추가하면 되고, 검색 성능이 안정적으로 O(1)을 유지하게 됨

###### 3. 가장 막혔던 문제와 해결 과정
- 문제 상황 또는 증상: 기본 요구사항에는 svg 파일에 대한 언급이 없었는데, Codestagram 이미지가 제대로 렌더링되지 않음
- 처음 추측한 원인: 파일 자체가 손상되었거나 경로 문제
- 원인을 확인하기 위해 시도한 방법: svg 파일의 특성을 조사해보니 XML 기반의 텍스트라는 것을 발견
- 실제 원인: Content-Type이 명시되지 않아 브라우저가 파일을 올바르게 해석하지 못함. 특히 svg는 이미지이지만 텍스트 기반이므로 charset도 필요
- 해결 방법: ContentTypeMap에 "svg" → "image/svg+xml; charset=utf-8" 추가
- 다음에 비슷한 문제가 생기면 먼저 확인할 것: 브라우저 개발자 도구의 Network 탭에서 Content-Type 응답 헤더를 먼저 확인할 것

###### 4. 오늘 잘한 행동(개발과 관련된 것)
- 어떤 행동이었는지: 기본 요구사항을 충족하는 것뿐만 아니라, 실제 동작 과정에서 놓친 부분을 능동적으로 발견하고 개선
- 그 접근이 도움이 된 이유: svg가 텍스트 기반이라는 특수성을 인식하고 charset을 함께 설정하여 완전한 지원이 가능해짐
- 다음에도 반복하고 싶은 점: 요구사항 기반 구현 후, 실제 동작 테스트에서 발생하는 엣지 케이스를 꼼꼼히 확인하는 태도

###### 5. 오늘 아쉬웠던 행동(개발과 관련된 것)
- 비효율적이었던 접근/놓치거나 부족했던 점: 완료 기록을 작성할 때 "String.lastIndexOf()를 활용하여 O(1)으로 맵에서 바로 검색"이라고 불명확하게 표현함. 실제로는 lastIndexOf()는 경로 길이에 따라 비용이 들고, HashMap.get()이 O(1)인 것인데 명확히 분리하지 않음
- 그렇게 된 원인: 구현 과정에서는 명확했지만, 회고를 작성할 때 표현의 정확성을 충분히 고려하지 않음
- 다음에는 다르게 해볼 구체적인 행동: 기술적 개선 사항을 기록할 때, "어느 단계에서 어떤 알고리즘이 몇 시간 복잡도를 가지는지" 명확하게 분리해서 작성할 것
