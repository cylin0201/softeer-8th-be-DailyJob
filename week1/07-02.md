###### 2. 오늘 가장 의미있었던 기술적 판단
- 내가 내린 판단: 정적 파일 경로를 `File` 기반(`src/main/resources/...`) 대신 `getClass().getClassLoader().getResourceAsStream()` 방식으로 전환하기로 함
- 그렇게 판단한 이유: `File` 방식은 JVM 작업 디렉토리에 의존적이라 jar 빌드 후 배포 시 resources 내부 파일을 찾지 못하는 문제가 있음
- 고려했지만 선택하지 않은 대안: 절대경로 하드코딩, 작업 디렉토리를 항상 프로젝트 루트로 고정하는 방식
- 이 판단이 코드 품질/테스트/유지보수에 미친 영향: 배포 환경 독립성 확보, 다만 `Files.probeContentType()` 사용 불가로 Content-Type은 별도 매핑 로직이 추후 필요해짐

###### 3. 가장 막혔던 문제와 해결 과정
- 문제 상황 또는 증상: `BufferedReader`로 요청 헤더를 읽는 로직에서 서버가 응답 없이 멈춤(hang)
- 처음 추측한 원인: 소켓 연결 자체가 안 되는 줄 알았음
- 원인을 확인하기 위해 시도한 방법: `readLine()`의 종료 조건과 HTTP keep-alive 특성을 다시 확인
- 실제 원인: `readLine() != null`을 종료 조건으로 써서, keep-alive로 연결이 안 끊기는 한 EOF(null)가 오지 않아 계속 블로킹됨
- 해결 방법: HTTP 헤더 섹션은 빈 줄로 끝난다는 스펙에 따라 `line.isEmpty()`를 종료 조건으로 변경
- 다음에 비슷한 문제가 생기면 먼저 확인할 것: 블로킹 지점이 스트림 읽기 루프의 종료 조건인지부터 점검

###### 4. 오늘 잘한 행동(개발과 관련된 것)
- 어떤 행동이었는지: 기능을 한 번에 완성하려 하지 않고 파일 경로 하드코딩 → 요청 파싱 → 클래스패스 기반으로 단계적으로 개선
- 그 접근이 도움이 된 이유: 각 단계에서 드러나는 문제(작업 디렉토리 의존성, Path Traversal, 404 처리 등)를 하나씩 명확히 짚을 수 있었음
- 다음에도 반복하고 싶은 점: 동작하는 최소 버전부터 만들고 점진적으로 리팩토링하는 방식

###### 5. 오늘 아쉬웠던 행동(개발과 관련된 것)
- 비효율적이었던 접근/놓치거나 부족했던 점: Path Traversal 취약점과 404 처리를 알고도 바로 코드에 반영하지 않고 다음으로 미룸
